## 5. 能否独立支持本次离线测试

**结论：可以支持，但有 3 项运行前提（均属 offline 设计口径，不是配置缺项）：**

1. **隔离输出根目录由运行参数给出**：`config/default.json` 的 `storage.offline_root` 为 `null`，按 output-schema §1.2 由运行参数临时指定 `<offline_root>/<run_id>/`；本轮不把本地临时路径写进配置。
2. **`run_id` 与输入文件清单由运行参数给出**：V1.4 的 real/synthetic 分区文件即输入，配置不登记输入路径（避免与项目归档混同）。
3. **不启动任何在线来源**：`sources.enabled=[]`，因此不需要群 ID、禅道实例、仓库 ID 与凭证引用 —— 这正好满足“不编造真实项目 ID/地址/凭证”的要求。

**不支持（按设计）**：`collect` / `process` / `analyze` 的正式运行。原因：`storage_root` 与 `persistence` 为 `null`、`prefix=TEST` 非真实前缀、来源全部关闭；`default.json` 明确 `storage_root=null` 时只允许 offline。转入正式测试前必须另建真实项目配置。
